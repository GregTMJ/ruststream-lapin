# 方法论

`ruststream-lapin` 如何测量自己：三个循环、在真实节点上的运行、受 Broker 限制的算式，以及代码的计数。
这套流程属于整个框架（[RustStream 的方法论](https://powersemmi.github.io/ruststream/latest/zh/architecture/benchmarks/methodology/)），
本页说明它在 RabbitMQ 上是什么样子。

## 三个循环 {/* #the-three-loops */}

同一个进程把每个场景跑三遍，三个循环只差一件事：消息由谁承载。

- **裸客户端。** 手写的循环直接驱动 `lapin`：接收、解码、ack。
- **Broker crate。** 本 crate，上面什么都没有：broker 建立连接，队列描述符打开订阅，一个循环从订阅的流里
  取出投递，解码并确认。
- **RustStream。** 用户写的服务：一个 `#[subscriber]` 处理器和包住它的应用。

其余一切在三个循环里都相同：连接、订阅拿到的 channel、队列的声明参数、预取窗口、ack 的位置、解码成
同一个类型、载荷字节、tokio 运行时和二进制文件。

消息体是 512 字节的 JSON，发布时不要求持久化。经典队列把它放在内存里，仲裁队列除了自己的复制存储没有
别的模式。

## 运行 {/* #the-run */}

- **每次运行一个新队列。** 每次运行都声明自己的队列，跑完就删掉，所以没有哪个循环会去处理上一次运行
  留下的东西。
- **测量窗口从第一次投递开始，到最后一条消息上的活干完为止**，三个循环都是这样。每个循环都在那一刻之后
  才确认投递，所以一次运行携带的数百万次确认里的这一次，在每个循环里都落在数字之外。
- **消息条数由一次探测决定**，使得每一次被测量的运行在任何机器上都不短于五秒。
- **三个循环交错进行**：裸客户端、crate、RustStream，共三轮。每个循环报告自己的最佳、中位和最差一轮。

当裸客户端把这次运行花在等服务器、而不是干活上时，这一行标为「受 Broker 限制」。这是一道算式：轮次之外的
一次探测测出服务器回答一个 `basic.qos` 要多久，当一次投递所需的往返加起来不少于一条消息所花时间的一半时，
就打上这个标记。往返时间和机器信息一起公布，算式可以自己核对。AMQP 的一次投递不用等自己的往返：服务器
主动推送消息体，也不回应确认。要等的是确认换回来的额度，而预取窗口把这份等待摊到窗口里的每一条消息上。

## 代码的计数 {/* #the-code-count */}

[开销图](index.md#cost-of-the-code)的每个场景都是用户写的服务，跑在 `LapinBroker` 上，连到 docker compose
环境里的节点，构建时不带 `testing` 特性。服务在启动时声明一个经典队列，用对照里相同的预取窗口消费它，
并且跑在单线程的 tokio 运行时上。队列由另一个线程在服务处理任何消息之前填好，填充要等节点确认了每一条
消息才结束。

指令数来自 callgrind，内存分配次数来自 DHAT。一个场景先跑一次投递，再跑 1000 次，再跑 2000 次。后两次
之差是一条消息的稳态开销，单次投递就是冷启动。

真实的节点按自己的节奏应答，所以服务线程等待套接字的次数每次运行都不一样。同一份代码运行七次，指令数
最多相差 2.4%，内存分配最多相差一个块。每个场景的分配下限比它测到的最大值高出千分之一，分配次数超过这个
下限时 `just bench-code` 失败。加上 `--baseline=main` 时，指令数多出百分之五以上也算失败；不带基线的运行
不限制指令数。失败的运行照样打印表格，并在表格下面列出每一项超出的限制，旧值与新值并排。

## 自己跑一遍 {/* #running-it-yourself */}

```bash
just bench
```

这条 recipe 从 `docker-compose.test.yml` 启动节点，跑完两个对照场景，停掉节点，然后重写
`docs/benchmarks/results.json`。它要花几分钟，并且需要整台机器。它会清空 `RUSTFLAGS`，所以二进制文件不会
绑定到构建它的那颗 CPU 上。

```bash
just bench-code
```

代码计数要花不到一分钟，需要 valgrind。基准测试运行器由 recipe 自己安装，版本与 `Cargo.lock` 锁定的一致。
在 recipe 名字后面加一个数字，可以设定每次被测量的运行投递多少条消息，例如 `just bench-code 2000`；公布的
数字是在默认值 1000 下测得的。在 `main` 上运行 `just bench-code --save-baseline=main` 记录基线，在分支上运行
`just bench-code --baseline=main` 与它比较。
