# 数字

`ruststream-lapin` 的基准测试数字测的是什么，以及不能从中得出哪些结论。

## 与裸客户端的对照 {/* #the-comparison-against-a-raw-client */}

同一行的三个循环可以互相比较，因为它们在同一个进程里、交错地、在同一个节点上运行。这一行不能拿去和另一个
Broker crate 公布的一行比较：不同的传输在每条消息上做的事并不一样。

标为「无法区分」的开销，是该循环与裸客户端之间的差值小于各自多次运行之间的波动。低于运行噪声的数字读起来
像是从未测到过的精度，所以不公布。

「受 Broker 限制」的一行，是裸客户端在大部分运行时间里都在等服务器的那一行。这时 crate 和运行时的工作发生在
这段等待之中，差值接近零。这是开销的下限，而不是对它的测量。

## 代码的开销 {/* #the-cost-of-the-code */}

指令数包括本 crate 的代码、它上面的运行时，以及 `lapin` 在服务线程上做的工作。这些数字是绝对值，框架自身的
开销也算在内；框架单独的开销由核心库在它的[基准测试页面](https://powersemmi.github.io/ruststream/latest/zh/architecture/benchmarks/)
上公布。同样的指令数在缓存未命中时要花更多时间，所以指令数不等于时间。

每个数字都是稳态值，即 1000 次投递的运行与 2000 次投递的运行之差。建立连接、打开 channel、声明队列和注册
消费者属于冷启动，只付一次。

## 这些数字不代表什么 {/* #what-they-do-not-mean */}

一行只是一个消费者、一个队列、一个很小的消息体，以及一个跑在回环地址上的节点。它测的是一次投递在这个 crate
里的开销，不是 RabbitMQ 能扛多少。

预取窗口决定了这些绝对数值。一个每条消息都确认、同时只允许一条未结清投递的消费者，每条消息都要花掉一个到
服务器的往返，三个循环就都落在这个往返的速度上。这些运行用的宽窗口，才让传输之上的那些代价有机会显现出来；
窗口一动，每一列一起动。

这些数字是一台机器在某一天的快照，构建信息记录在旁边。它们由人手工重测，测量期间机器只跑这一项：它们显示的
差值，比与其他任务共用的机器上的噪声还小。
